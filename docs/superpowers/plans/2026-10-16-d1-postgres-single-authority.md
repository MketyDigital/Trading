# D1/PostgreSQL single-authority migration plan

## End-to-end progress plan

1. **Schema and repository coverage — complete locally.** Keep the production metadata inventory authoritative, generate both backend schemas, map every table/RPC to migrate/retire, and test D1 schema coverage plus PostgreSQL static parity. Live PostgreSQL application remains part of backend conformance below.
2. **Worker integration — in progress.** Compose repositories once per request/runtime; replace every active Supabase call in V1 fetch, queue, cron, connector, Telegram, and recovery paths. Keep authentication/provider services separate only where they do not store Trading data. Retired legacy handlers must be explicitly unreachable and excluded from runtime imports.
3. **Replication and conformance — pending.** Ensure every authoritative write has an atomic outbox event; complete bounded replication, retry/quarantine/alerting and lag metrics; run the same behavior suites against real D1 and PostgreSQL and scan for zero Trading Supabase runtime dependencies.
4. **Existing-database rehearsal — pending.** Use the existing Coolify PostgreSQL service and database only; do not provision another Coolify DB. Apply the schema-only migrations to `trading_storage` after CI and scope checks pass, with all authority/execution defaults fenced/off. Use the existing D1 staging database for adapter and schema checks, then compare counts/checksums/constraints and trading state before any authority change. Rehearse replication and measure lag/RPO/cost without enabling trading from shadow data.
5. **Switch rehearsal — pending.** Exercise D1→PostgreSQL→D1 with cron/queue/ingress fencing, drained in-flight operations, broker reconciliation, parity checks, rollback, and LIVE disabled. Document measured downtime and recovery criteria.
6. **Production cutover review — pending.** Only after all prior evidence is green, prepare backup and a concrete cutover runbook. Review the evidence and execute the approved switch; verify DEMO behavior and monitor before removing Supabase credentials/dependencies.

Progress checkpoints are recorded below. No production authority or Worker deployment changes are part of the local implementation phase.
